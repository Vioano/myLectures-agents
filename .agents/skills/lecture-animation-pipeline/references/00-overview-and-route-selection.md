# Overview And Route Selection

This project is a Bilibili teaching-video production repo. The default separation is:

- `vault/`: formal course notes, scripts, storyboards, and notebooks.
- `videos/NNNN-slug/`: production directory for animation code, episode assets, draft material, exports, timeline, logs, review tracking, and video-specific tooling.
- `shared/`: cross-video style, character assets, sound assets, and reusable material.
- `lib/`: cross-video helper code.

Do not treat the daily learning vault as a production directory. Use it only as a source of ideas or knowledge when explicitly needed.

## Two Audio Routes

Choose the route explicitly before building timeline and animation:

1. **Voice conversion route**: keep the original oral recording's pacing, pauses, and live delivery; separate vocals; transcribe SRT; convert voice color. Use `10-voice-conversion-workflow.md`.
2. **TTS route**: rewrite a production script into TTS-friendly segments; synthesize full audio; transcribe the synthesized result; then build timeline. Use `11-tts-workflow.md`.
3. **Hybrid route**: compare both routes on small segments; do not mix timing assumptions. If audio is cut, update audio, SRT, and timeline together.

The line "this directory explores original oral recording + vocal separation + voice conversion" describes only the voice-conversion production directory, not the whole project. The TTS directory has its own flow.

## Required Shared Artifacts

For each video production directory, keep these artifacts current:

- `README.md`: route summary, current voice/audio choice, source draft, file map, and next commands.
- `script.md`: production narration units. Each `Sxxx` segment is a synthesis and timeline unit when the route is TTS.
- route-specific speaking rules, such as `tts-speaking-rules.md` for TTS projects.
- `storyboard.md`: optional production storyboard derived from or pointing back to the formal vault storyboard.
- `timeline.json`: timing contract for narration, visual, audio, character, sonification, and BGM suggestions.
- `formula-manifest.md`: all important formulas, whether spoken or only shown.
- `experiment-log.md`: operation log, decisions, failures, fixes, outputs, QC, and process reflections.
- `src/theme.py`: shared theme constants and helpers for the video.

Formal authoring lives in `vault/videos/NNNN-slug/`: `script.md`, `storyboard.md`, the main note, and `notebook.ipynb`. The production directory may keep a working `storyboard.md` or scene-local `src/<scene_slug>.stage.md`, but the file must state whether it is derived from the vault storyboard or is implementation-only stage direction.

## New Episode Initialization

When starting a new episode, initialize the real production directory before attempting audio or Manim:

- create the episode root, `src/`, `scripts/`, `assets/`, `references/`, `draft/`, and `exports/` with an `exports/README.md` committed;
- create the project/status entry file when the repo structure uses one, plus update the catalog/index if the branch owns that index;
- write `README.md`, `script.md`, route-specific speaking rules, `formula-manifest.md`, `storyboard.md`, `timeline.json`, and `experiment-log.md`;
- create or copy a local `src/theme.py` that uses the shared palette and video-local paths;
- for TTS routes, include or adapt scripts for full TTS rendering, normalization, stitching, and transcription;
- mark `timeline.json` as a pre-audio placeholder until full TTS audio and SRT/alignment exist. Use `null`, `TBD`, or an explicit placeholder status instead of inventing timings.

This initialization pattern reflects episode 0001's actual TTS production more closely than a minimal `src/assets/exports` scaffold. The early artifacts should be honest: formulas can be pending, storyboard can be pre-audio, and timeline can lack timecodes, but the route, source draft, audio choice, and next commands should be clear.

## Output Contract

Before any render, review handoff, QC extraction, or final stitch, follow `41-production-output-contract.md`.

Core distinction:

- `assets/` and `shared/` contain source assets that may be tracked when appropriate.
- `media/`, `draft/`, and `exports/` are generated by default and stay out of git.
- `exports/` holds generated artifacts that entered the production chain; `draft/` holds experiments and disposable tests.
- `review/` holds tracked coordination documents; review MP4s and QC frames live under `exports/`.

## Branch And Git Discipline

- Inspect `git status --short` before edits.
- Keep unrelated user or other-agent changes untouched.
- Commit meaningful checkpoints.
- Use `dot_clean .` before committing on `/Volumes`.
- Do not stage `exports/*`, `.DS_Store`, `._*`, `.venv/`, generated caches, or unrelated work.
- Do not stage `media/`, `draft/`, generated Manim caches, review MP4s, QC frames, or final stitched videos unless explicitly requested.
- Production work must happen inside `/Volumes/bocchi/myLectures`; each video directory must be under `videos/NNNN-slug/`.
- Do not create sibling worktrees or clones such as `/Volumes/bocchi/myLectures-0002-*` for production files. This splits lessons that should be siblings under the same `videos/` directory.
- Use Git branches, commits, review files, and explicit ownership to isolate agents. External CLI workers should be read-only by default; if they write, switch this repo to the task branch first and limit the allowed paths.
