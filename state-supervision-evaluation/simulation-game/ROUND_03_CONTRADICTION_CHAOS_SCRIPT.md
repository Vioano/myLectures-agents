# Round 03 · 朝令夕改与矛盾识别压力演练

> 仅供 game master 与事后评估使用。黑盒 Agent 不得读取本文件、源码、
> 数据库、测试、旧轮报告或隐藏 oracle。本轮只生成微型占位制品，不做真实
> TTS、ASR、Manim、3D、A-roll 剪辑或发布。

## 目标与停止规则

- 目标时长 12 分钟；13:30 后不再引入剧情；15:00 硬停止并冻结事实。
- 初始状态仍是正常的全 TTS + 2D Manim 计划，系统不得预知后续变化。
- 同时观察 Human Interface、Agent Interface、后端事件与跨界面因果链。
- 不以“全部完成”为成功条件；能够安全阻塞、精确求助和诚实停机也是成功。

## 三种变化必须被区分

1. **显式替代**：较新的要求明确取消旧路线，例如“3D 插段改为 A-roll”。
   系统应原子 supersede 旧路线、只重接受影响的消费者，并保留审计历史。
2. **局部新增**：例如新增角色 sprite，但只影响指定镜头。无关口播与前半
   视觉分支应继续，不得全局返工。
3. **未解决矛盾**：两个仍然有效、权威相同的要求不能同时满足。系统不得靠
   时间顺序或模型猜测静默选边；必须保留两条原文和来源、阻塞最小受影响范围，
   给 Human 形成一个可操作的裁决项，并让 Agent 知道为什么停。

## 矛盾判定 oracle

- “后半 TTS 改真人录音”“3D 改 A-roll”包含明确取消关系，是可自动执行的
  route supersession，不需要 Human 再裁决一次。
- “必须使用 sprite”与“许可证撤回，禁止使用”都被声明仍然有效，是硬矛盾。
- “精确插入 6 秒”与“总时长/所有片段时码均不可变且无空隙”是硬矛盾。
- 语义矛盾可以由强模型发现；确定性 Harness 的职责是把发现变成结构化阻塞、
  最小失效范围、Human 决策项和可重放的恢复，而不是自己替 Human 选答案。
- 如果 Agent 只记录普通 observation 后继续制作，或系统把两个 append block
  标成 `conflict_count: 0` 且没有阻塞/提醒，本项判失败。

## 黑盒 Agent 必答

- 每次路线变化或冲突在什么注意力边界进入？是否中断了 live lease？
- capsule 是否只含该任务需要的变化，还是泄漏了整集剧情？
- 两条冲突原文、来源 ID 和有效状态是否都可见？
- 不看源码的情况下，是否能找到合法的 `gap` / 求助 / 恢复动作？
- Human 裁决后，旧冲突是否从 active context 消失但仍保留审计？
- 有多少次额外 `next`、`explain`、帮助读取或重复轮询是由于界面不确定？
- “增加并行 author”是由哪一个角色、基于什么 backlog/关键路径事实决定的？
- 新 author 数量是否精确到可验证的并行 lane，而不是拍脑袋加人？
- 图上的并行支路是否真的形成重叠 lease；若没有，是规划、调度还是执行失败？
